## 1. 产品概述

### 1.1 产品定位

**摄像头实时翻译**是一款利用计算机视觉（OCR）和机器翻译技术，通过设备摄像头实时捕获画面中的文字，并即时将其翻译为用户目标语言的工具型应用。用户在摄像头取景框中看到的是"原文 + 译文"同屏叠加显示的画面，无需拍照、无需手动输入，即见即译。

### 1.2 产品愿景

> 消除现实世界中一切文字阅读障碍，让每个人都能用眼睛"读懂"任何语言。

### 1.3 核心价值主张

| 维度 | 价值 |
|------|------|
| **即时性** | 无需拍照，摄像头对准即翻译，延迟 < 1 秒 |
| **沉浸感** | 译文直接叠加在原画面文字的旁边/下方，阅读体验自然 |
| **准确性** | 多引擎翻译可选，用户可切换对比 |
| **离线能力** | 支持离线 OCR + 离线翻译，境外无网络也能用 |

### 1.4 竞品对比

| 功能 | Google 翻译 | 有道翻译官 | 本产品目标 |
|------|------------|-----------|----------|
| 拍照翻译 | ✅ | ✅ | ✅（瞬时完成） |
| 实时摄像头翻译 | ✅（AR 模式） | ❌（仅拍照） | ✅（核心功能，体验更优） |
| 双语同屏 | 部分支持 | 不支持 | ✅（核心特色） |
| 离线翻译 | ✅ | ✅ | ✅ |
| 多语种 | 100+ | 50+ | 50+（首批） |
| 对话翻译 | ✅ | ✅ | 二期 |

## 2. 目标用户与场景

### 2.1 用户画像

#### 画像 A：出境旅行者
- **年龄**：25-55岁
- **特征**：英语水平有限，自由行时看不懂菜单、路牌、说明标签
- **痛点**：每次掏出手机→拍照→等待翻译→对照原文太麻烦
- **期望**：开着摄像头扫过去就能懂

#### 画像 B：留学生 / 海外生活者
- **年龄**：18-30岁
- **特征**：日常需要阅读外文教材、文件、超市标签、账单
- **痛点**：频繁查词打断阅读流，拍照翻译效率低
- **期望**：像"透视眼镜"一样直接看懂

#### 画像 C：商务人士
- **年龄**：30-50岁
- **特征**：经常参加国际展会、阅读外文合同/资料
- **痛点**：专业术语看不懂，需要准确翻译而非意译
- **期望**：专业词汇翻译准确，支持保存翻译记录

### 2.2 核心使用场景

| 优先级 | 场景 | 说明 |
|--------|------|------|
| P0 | 餐厅菜单翻译 | 摄像头对准菜单，实时显示中文译文 |
| P0 | 路牌/指示牌翻译 | 行走中快速识别方向标识 |
| P1 | 商品标签/说明书 | 购物时查看成分、使用说明 |
| P1 | 书籍/文件翻译 | 阅读外文资料、合同 |
| P2 | 展会/会议PPT | 大屏幕外文内容实时翻译 |

### 2.3 典型用户故事

> **作为**一个去日本旅行的中国游客，
> **我希望**打开手机摄像头对准日文菜单就能直接看到中文，
> **以便**我不用麻烦服务员、不用下载其他翻译App、几秒内就能点餐。

> **作为**一个在美国读书的留学生，
> **我希望**面对一份英文实验报告的表格数据也能准确翻译，
> **以便**我高效完成实验分析而不用逐词查字典。

> **作为**一个参加德国工业展的商务人士，
> **我希望**将翻译历史自动保存并支持导出，
> **以便**回国后整理展会资料与团队分享。

## 4. 功能详细说明

### 4.1 实时翻译取景器（P0 ★核心功能）

#### 4.1.1 功能描述

用户打开应用后直接进入全屏取景器，摄像头画面实时显示在屏幕上。当画面对准包含文字的场景时，系统自动识别文字区域，在画面上以"高亮框标注原文 + 浮动卡片显示译文"的形式呈现。

#### 4.1.2 交互流程

```
[打开App] → [自动进入取景器] → [对准文字]
    → [0.3s内完成OCR识别] → [0.3s内完成翻译]
    → [译文以浮动卡片出现在原文下方/旁边]
    → [画面移动 → 检测到新文字 → 旧译文消失 → 新译文出现]
```

#### 4.1.3 交互细节

| 交互项 | 说明 |
|--------|------|
| **文字检测框** | 检测到的文字区域用半透明圆角矩形框出，细线绿色边框 |
| **译文卡片** | 位于原文下方（默认），半透明白底/暗底（跟随系统），圆角卡片 |
| **原文保留** | 原文区域保持可见，不被译文遮挡；译文以指示线连接原文区域 |
| **自适应对比度** | 译文卡片背景色根据当前画面亮度自动调整透明度，保证可读性 |
| **检测刷新频率** | 每秒检测 3-5 次（200-333ms/次），平衡速度与功耗 |
| **多区域同时翻译** | 画面中同时出现多块文字区域时，分别标注并翻译（最多6个区域） |
| **区域去抖** | 同一文字区域在连续帧中不做重复翻译请求，仅在文字内容变化时更新 |

#### 4.1.4 状态说明

| 状态 | 画面表现 | 触发条件 |
|------|---------|---------|
| **待机态** | 取景器纯净画面，无任何标注 | 未检测到文字 |
| **检测中** | 文字区域出现呼吸动画虚线框 | OCR 进行中 |
| **翻译中** | 原文区域出现实线框，译文区显示"..."加载动画 | 翻译请求中 |
| **翻译完成** | 原文区域实线框 + 译文卡片内容 | 翻译结果返回 |
| **翻译失败** | 原文区域实线框 + 译文区显示"翻译失败" + 重试图标 | 网络异常/引擎异常 |
| **冻结态** | 画面停住，顶部显示"已冻结"标签 | 用户点击冻结按钮 |

#### 4.1.5 边界条件

- 暗光环境：自动提示开启闪光灯，闪光灯打开后进入补光模式
- 文字过小：提示"请靠近些"，以摇摆动效引导用户
- 文字模糊：在译文卡片上标注低置信度图标（灰色问号）
- 倾斜严重：提示"请正对文字"
- 无文字画面：取景器保持干净，不显示任何UI干扰
- 后台切换：App切到后台时自动释放摄像头，回前台自动恢复

### 4.2 语言设置（P0）

#### 4.2.1 功能描述

用户可选择翻译方向。默认模式为"自动检测 → 中文"，用户也可手动指定源语言以获得更准确的翻译结果。

#### 4.2.2 交互流程

```
[取景器底部语言栏]
    ├── 左侧：源语言选择器（默认"自动检测"）
    ├── 中间：双向箭头（点击交换语言方向）
    └── 右侧：目标语言选择器（默认用户系统语言）
```

#### 4.2.3 语言列表（v1.0首批支持）

| 语系 | 语言 |
|------|------|
| 东亚 | 简体中文、繁体中文、日语、韩语 |
| 欧洲 | 英语、法语、德语、西班牙语、葡萄牙语、意大利语、俄语 |
| 东南亚 | 泰语、越南语、印尼语、马来语 |
| 南亚 | 印地语、阿拉伯语 |
| 其他 | （共支持50+种语言，完整列表见附录） |

#### 4.2.4 自动检测逻辑

- 画面中出现文字的2秒内推测语种
- 连体字符、多语种混合时，以面积占比最大的语种为准
- 自动检测结果在翻译结果旁标注语种标签（如"检测：日语"），用户可一键纠正

### 4.3 翻译控制（P0/P1）

#### 4.3.1 画面冻结（P0）

- **触发**：点击取景器中央的"冻结"按钮（或长按屏幕）
- **效果**：画面暂停，OCR/翻译也暂停，用户可仔细查看当前帧译文
- **恢复**：再次点击"解冻"，恢复实时检测
- **使用场景**：看菜单时冻结一屏，慢慢对比每道菜的翻译

#### 4.3.2 拍照快译（P1）

- **触发**：点击右下角快门按钮
- **效果**：截取当前帧并保存至本地相册 + 翻译历史，同时画面冻结3秒供查看
- **与冻结的区别**：快译会保存图片，冻结不会

#### 4.3.3 翻译引擎切换（P1）

| 引擎 | 优势 | 适用场景 |
|------|------|---------|
| 默认引擎（百度/Google） | 通用翻译质量好 | 日常场景 |
| DeepL | 欧洲语种质量高 | 专业文档 |
| 术语库引擎 | 支持自定义术语表 | 专业领域 |

用户可在设置中选择默认引擎，或在取景器顶部快速切换（长按引擎图标）。

### 4.5 历史与收藏（P1/P2）

#### 4.5.1 翻译历史（P1）

- 自动记录每次"拍照快译"的图片 + 原文 + 译文 + 语种 + 时间戳
- 列表视图：缩略图 + 原文前20字 + 译文前20字 + 时间
- 详情视图：全屏图片 + 原文/译文对照文本
- 支持左滑删除
- 存储限制：最多保存500条，超出后自动清理最早记录

#### 4.5.2 翻译收藏（P2）

- 在翻译历史中标记为收藏
- 独立的收藏列表
- 支持导出为文本文件（TXT/CSV）

#### 4.5.3 历史搜索（P2）

- 支持按原文关键词、译文关键词、语种、日期范围搜索

### 4.7 用户账户系统（P0 ★v1.01 新增）

#### 4.7.1 功能概述

用户通过手机号或第三方账号快速注册登录，实现翻译历史、收藏、离线包等数据的云端同步。未登录状态下核心翻译功能正常使用（游客模式），登录后可解锁云同步、多设备漫游、高级设置备份等增值能力。

**设计原则：**
- **先使用后注册** — 游客可无限制使用翻译功能，仅在需要云同步时引导注册
- **一键注册** — 手机号验证码即注册即登录，无密码流程
- **隐私优先** — 用户翻译内容默认本地存储，仅用户主动开启同步后才加密上传云端

#### 4.7.2 注册方式

| 方式 | 流程 | 优先级 |
|------|------|--------|
| **手机号 + 验证码** | 输入手机号 → 获取6位验证码 → 验证通过 → 自动创建账号 | P0 |
| **微信登录** | 点击微信图标 → 跳转微信授权 → 授权通过 → 绑定手机号(可选) → 创建账号 | P0 |
| **Apple ID 登录** | 点击Apple图标 → 系统原生Face ID/Touch ID验证 → 一键登录（iOS必选） | P0 |
| **Google 登录** | 点击Google图标 → OAuth授权 → 创建账号 | P1 |
| **邮箱注册** | 输入邮箱 → 设置密码 → 邮箱验证 → 创建账号 | P1 |

#### 4.7.3 登录流程

```
[启动App] → [首页/取景器]
    ├── 游客模式（默认）：直接进入取景器 → 使用完毕后可在"我的"页面注册
    └── 已有账号：
        ├── 手机号验证码登录（主推，即注册即登录）
        ├── 微信一键登录（已授权过则自动登录）
        ├── Apple/Google 一键登录
        └── 邮箱密码登录（备选）
```

**Token 管理：**
- JWT Access Token 有效期 7 天，Refresh Token 有效期 30 天
- 用户主动退出登录后清除本地 Token
- 检测到异常设备登录时推送安全通知并强制下线

#### 4.7.4 游客模式与注册引导

| 场景 | 行为 |
|------|------|
| **首次安装启动** | 直接进入取景器，顶部显示半透明提示条"登录后可同步翻译记录"× 关闭按钮 |
| **首次拍照快译后** | 弹出 BottomSheet："保存到云端，换手机也不丢失" → 立即注册 / 暂不需要 |
| **首次使用离线包下载** | 提示"登录后下载更快，支持断点续传" |

#### 4.7.6 云端数据同步（P0）

| 同步内容 | 说明 | 冲突策略 |
|---------|------|---------|
| 翻译历史 | 拍照快译的图片+原文+译文+元数据 | 以最后修改时间为准 |

| 个人资料 | 头像、昵称、邮箱 | 以最后修改时间为准 |

**同步策略：**
- **增量同步** — 仅上传/下载变更的数据，减少流量消耗
- **自动同步频率** — App 启动时触发一次 + 进入后台前触发一次 + 用户手动触发
- **同步状态提示** — 状态栏图标旋转动画表示同步中，完成后显示 ✓
- **冲突处理** — 时间戳比对，自动选择最新版本，冲突项存入"待处理"列表供用户手动选择

## 6. 界面设计原则

### 6.1 设计理念

> **摄像头优先（Camera-First Design）**：UI 永远不遮挡取景器核心区域。所有控件都最小化、半透明化，让用户专注于"看到的内容"而非"操作界面"。

### 6.2 布局规范

```

│                             │
│      取景器画面              │
│   ┌─────────┐              │
│   │Hello     │ ← 原文框     │
│   └─────────┘              │
│   ┌─────────┐              │
│   │你好      │ ← 译文卡片   │
│   └─────────┘              │
│                             │
│                             │
├─────────────────────────────┤
│ 自 动检测 ←→ 简 体中 文      │  ← 语言栏（半透明底）
├─────────────────────────────┤
│  冻结  │  ───📷───  │ 历史 │ 我的  │  ← 操作栏
```

## 7. 非功能需求

### 7.1 性能指标

| 指标 | 目标值 | 测量方法 |
|------|--------|---------|
| **OCR识别延迟** | < 200ms（纯文本）/ < 400ms（复杂排版） | 从帧捕获到文字输出的时间 |
| **翻译延迟** | < 300ms（在线）/ < 500ms（离线） | 从文字输出到译文返回的时间 |
| **端到端延迟** | < 1秒（从对准到译文显示） | 用户感知时间 |
| **首屏加载** | < 2秒（从冷启动到取景器可用） | App启动时间 |
| **帧率** | ≥ 30fps（取景器流畅度） | 摄像头预览帧率 |
| **CPU占用** | < 30%（中端设备持续运行） | 30分钟持续使用平均CPU |
| **内存占用** | < 200MB | 运行时内存峰值 |
| **耗电** | < 15%每小时（中端设备） | 屏幕亮 + OCR持续运行 |
| **离线包大小** | < 80MB / 语种 | 单语言双向离线包 |
| **APK/IPA大小** | < 80MB | 不含离线包的安装包 |

### 7.2 兼容性

| 平台 | 要求 |
|------|------|
| **iOS** | iOS 15.0+，支持iPhone 11及以上机型 |
| **Android** | Android 10.0+（API 29+），支持主流品牌中高端机型 |
| **平板** | iPadOS 15.0+（第一阶段适配，非重点） |

### 7.3 网络要求

- **在线模式**：需要稳定的网络连接（WiFi / 4G / 5G）
- **弱网处理**：请求超时 3 秒 → 自动重试一次 → 失败则提示"网络不佳，建议切换离线模式"
- **离线模式**：需预先下载对应语种的离线包，OCR + 翻译全部本地完成，无网络请求

### 7.4 安全性

- 摄像头数据**不上传服务器**（本地处理OCR）
- 在线翻译请求传输使用HTTPS加密
- 不在服务端存储用户的翻译内容
- 本地历史数据存储使用SQLite加密（SQLCipher）
- 云端同步数据使用AES-256加密存储
- 用户密码使用bcrypt加盐哈希存储（不低于12轮）
- 验证码发送频率限制：同一手机号60秒内只能获取1次，每天上限10次
- JWT Token 签名使用RS256非对称加密算法
- 敏感操作（注销账户、修改密码、更换绑定）需短信验证码二次确认
- 登录态敏感操作（修改密码后、异地登录）主动失效所有已签发Token
- 第三方OAuth授权遵循最小权限原则，仅获取昵称、头像、OpenID
- 符合GDPR和国内个人信息保护法
- 定期第三方安全渗透测试（每版本发布前）

### 7.5 可用性

| 维度 | 要求 |
|------|------|
| 无障碍 | 支持VoiceOver/TalkBack朗读译文 |
| 国际化 | UI字符串分离，支持多语言界面 |
| 横竖屏 | 同时支持横屏和竖屏使用，UI自适应 |
| 折叠屏 | 不做专门适配，但UI需保证基本可用 |

## 11. 风险与应对

| 风险 | 影响 | 概率 | 应对措施 |
|------|------|------|---------|
| OCR在复杂背景下准确率低 | 用户体验差 | 中 | 多模态OCR融合（文字检测+语义分割），低置信度时降级展示 |
| 实时翻译延迟过高 | 产品核心价值受损 | 中 | 本地推理优先，在线作补充；帧间去抖减少请求量 |
| 离线模型体积过大 | 下载率低 | 中 | 模型量化压缩，分语种子集下载（日常用语+旅行用语） |
| 第三方翻译API涨价/停止服务 | 产品不可用 | 低 | 自研翻译模型，同时对接3家以上API互为备份 |
| 摄像头持续运行耗电发热 | 用户抱怨 | 高 | 检测到画面静止时降低检测频率，自适应帧率策略 |
| App Store审核政策风险 | 上线延期 | 低 | 提前研究审核指南，摄像头权限申请文案真实明确 |
| 专利风险（AR翻译） | 法律纠纷 | 低 | 上线前做专利检索，必要时调整交互方案 |
| 用户数据泄露 | 品牌信任崩塌、法律处罚 | 低 | 云端数据加密存储；定期安全审计；渗透测试 |
| 短信验证码被刷 | 运营成本失控 | 中 | 图形验证码前置 + IP频率限制 + 单日上限 |
| 第三方登录不可用 | 用户无法登录 | 低 | 确保手机号验证码登录为兜底方案 |
| 账号注销后冷静期客诉 | 用户不满 | 低 | 明确告知30天冷静期，提供即时撤销入口 |
