# 课堂助手改进方案

| 字段 | 内容 |
| --- | --- |
| 产品名称 | LiveTrans Voice 课堂助手 |
| 文档版本 | v1.0 |
| 定位 | 面向学生的课堂录制、课后汇报与学习问答助手 |
| 核心原则 | 音频优先、视觉可选、所有结论可追溯 |

## 1. 目标与边界

将现有的实时转录翻译工具升级为课堂助手：学生开始课堂后，系统稳定录制教师讲课音频；在允许且设备支持时采集黑板或投影内容；课堂结束后自动生成可回听、可校验的课堂汇报；学生可在独立的助手对话页中检索并提问自己的课堂资料。

第一阶段不做自动代替学生完成作业、不做对学生或教师的人脸识别、不默认保存完整课堂视频，也不将模型推测写成课堂事实。

## 2. 用户与核心价值

核心用户为需要记录外语或专业课堂的学生。其目标不是取得一段视频，而是课后快速得到可靠的课堂内容、重点、作业和复习入口。

| 痛点 | 对应能力 |
| --- | --- |
| 听课时来不及记笔记 | 全程音频录制、转录与时间轴 |
| 板书、公式或 PPT 容易遗漏 | 可选视觉采集、关键帧和 OCR |
| 课后回听效率低 | 自动课堂汇报与可跳转证据 |
| 多节课资料分散 | 跨课堂检索与对话助手 |
| AI 总结可能出错 | 每条结论带录音时间、转录句号或课件页码 |

## 3. 完整用户流程

```text
选择课程 → 开始课堂
  ├─ 初始化麦克风（必需）→ 录音、分片上传、实时或课后转写
  └─ 初始化摄像头（可选）→ 关键帧采集、板书/PPT OCR
结束课堂 → 素材整理 → 课堂汇报 Agent → 引用校验 → 展示汇报
                                                   ↓
                                      对话助手 / 复习卡 / 导出
```

### 3.1 上课前

- 选择或新建课程：课程名、授课语言、翻译语言、地点和可选课程标签。
- 默认进入“音频课堂模式”；用户可主动开启“板书/PPT 采集”。
- 首次使用分别申请麦克风与摄像头权限，并显示课堂录音录像许可提示。

### 3.2 上课中

- 全程保存音频与带时间戳的转录；已有实时翻译能力可作为增强体验。
- 支持暂停、恢复、结束和一键收藏；收藏可标为重点、疑问、考点或定义。
- 视频仅面向黑板/投影幕。视觉模块检测画面变化、PPT 翻页、板书新增或公式区域，缓存/上传候选帧。
- 摄像头不可用、权限被拒绝或上传失败时，自动保持音频课堂，不中断录音、转写或课堂结束流程。

### 3.3 下课后

- 课堂状态由 `recording/paused` 进入 `processing`，完成后变为 `completed`；前端显示汇报生成进度。
- Agent 生成课堂汇报，用户可编辑标题、确认作业、删除错误板书图，随后导出或分享。

## 4. 模式与降级设计

| 模式 | 采集内容 | 产物 | 适用情况 |
| --- | --- | --- | --- |
| 音频课堂（默认） | 音频、转录 | 文字汇报、时间轴、录音回放 | 摄像头不支持、用户未授权或追求低成本 |
| 视觉增强课堂 | 音频 + 候选关键帧 | 音频课堂产物 + 板书/PPT图片与 OCR | 黑板、公式、投影内容较多 |
| 完整原始音视频保存（可选） | 音频 + 全程视频 | 上述产物 + 原视频 | 用户获得录制许可且确有回看需求 |

不得以一次 `getUserMedia({ audio: true, video: true })` 同时初始化两种设备。应先独立初始化音频，录音成功即允许开始课堂；视频失败只写入 `video_status=unavailable` 并提示用户“已继续音频课堂模式”。若麦克风权限被拒绝或设备不可用，才禁止开始课堂。

## 5. 视觉采集方案

不采用“检测到关键词才开始录像”：关键板书常先出现、后解释，公式和图示也未必伴随固定关键词，容易漏采。

推荐流程：

1. 客户端以低帧率采集（建议 1–2 FPS）或仅在画面变化时取帧，不将每一帧送入大模型。
2. 使用本地/服务端轻量算法做模糊度、重复帧、画面变化、文本/公式区域检测。
3. 每个变化事件保留 1–3 张清晰候选图；必要时保留前后 20–40 秒本地缓存视频片段。
4. 课后仅将 20–60 张候选关键帧交给 OCR/视觉模型，抽取文字、公式说明或图表描述。
5. 将结果与录音时间轴、转录句子对齐，并由用户在汇报中查看或删除。

默认固定镜头对准黑板或投影，不进行学生人脸识别。原始视频须加密存储、单独授权并提供自动删除期限。

## 6. 课堂汇报 Agent

课堂结束事件触发后台任务。该 Agent 是受控工作流，不是自由发挥的聊天机器人。

```text
素材准备
→ 转录整理
→ 重点/作业/术语提取
→ 视觉内容合并
→ 结构化汇报生成
→ 引用与事实校验
→ 保存、通知与可重试
```

### 6.1 输入

- 原始转录句子、句子序号、音频起止时间和识别置信度。
- 用户收藏及其标签和备注。
- 关键帧 OCR、对应时间、图片 URL。
- 可选的课程资料、术语表和此前课堂汇报。

### 6.2 输出

汇报应以 JSON 保存，再由前端渲染。每个内容项必须携带至少一个引用。

```json
{
  "overview": "本节课介绍热力学第二定律及熵的定义。",
  "topics": [{"title": "熵的定义", "citation_orders": [18, 19]}],
  "key_points": [{"text": "孤立系统的熵不会自发降低。", "citation_orders": [18]}],
  "assignments": [{"text": "完成第 4 章习题。", "due_date": null, "needs_confirmation": true, "citation_orders": [64]}],
  "terms": [{"term": "Entropy", "meaning": "熵", "citation_orders": [18]}],
  "visuals": [{"image_id": 25, "caption": "第二定律公式", "citation_orders": [19]}],
  "uncertain_items": []
}
```

### 6.3 可靠性规则

- 模型只可根据输入材料作答；每一结论的 `citation_orders` 都必须存在且属于当前用户可访问的课堂。
- 识别出作业、考试范围、日期但无法明确确认时，写入 `needs_confirmation=true`，前端显示“待确认”。
- 转录置信度低、视觉 OCR 冲突或缺少证据时，保留为待确认项或删除，不生成肯定结论。
- 模型调用失败时回退到现有抽取式简报，确保课堂结束后仍可获得基本汇报。

## 7. 独立学习助手对话页

新增“学习助手”页面，保留现有单节课堂问答，并扩展为三种检索范围：本节课堂、当前课程、我的全部资料。

| 用户问题 | 检索范围 | 示例回答证据 |
| --- | --- | --- |
| “老师布置了什么作业？” | 当前课堂/课程 | 汇报的作业项 + 转录 #64 + 32:18 |
| “熵在哪几节课讲过？” | 当前课程 | 多节课堂主题、转录片段与时间点 |
| “基于我的疑问出 5 道题” | 当前课程 | 用户收藏的疑问和定义卡片 |

回答页面由答案、来源卡片和后续操作组成。来源卡片能打开课堂回顾页并跳转到对应录音时间；后续操作包括“加入复习”“收藏答案”“继续追问”和“纠正本条内容”。

### 7.1 对话 Agent 流程

```text
用户问题 + 当前范围
→ 权限过滤（仅当前用户资料）
→ 关键词 + 语义混合检索
→ 选取带来源的少量证据
→ 生成回答
→ 引用校验
→ 返回答案、引用和置信提示
```

初版可复用现有按转录/收藏检索与引用校验；第二阶段为转录、汇报、OCR、课件切块建立向量索引，支持跨课堂语义检索。系统不得把其他用户的课堂、未授权课程或不存在的引用传给模型。

## 8. 数据与接口改造

现有 `lectures`、`transcriptions`、`bookmarks` 与 `lecture_briefings` 可继续复用。建议新增或扩展如下：

| 对象 | 关键字段 | 用途 |
| --- | --- | --- |
| `lectures` 扩展 | `audio_status`、`video_status`、`processing_status`、`visual_summary_available` | 表达音视频独立状态与处理进度 |
| `lecture_visual_assets` | `lecture_id`、`captured_at_ms`、`image_url`、`ocr_text`、`quality_score` | 保存关键板书/PPT帧及 OCR |
| `courses` | `user_id`、课程名、教师、语言、标签 | 归档多次课堂 |
| `course_materials` / `content_chunks` | 来源、文本、页码/时间、向量 | 课件与跨课检索 |
| `assistant_conversations` / `assistant_messages` | 用户、范围、问题、回答、引用 | 保存学习助手历史 |
| `review_items` | 课程、来源、掌握度、下次复习时间 | 后续间隔复习 |

新增接口建议：

- `POST /api/lectures/{id}/visual-assets`：上传候选帧；失败不影响音频接口。
- `GET /api/lectures/{id}/report`：读取结构化课堂汇报。
- `POST /api/lectures/{id}/report/regenerate`：人工触发重新生成。
- `POST /api/assistant/conversations`：创建学习助手会话。
- `POST /api/assistant/conversations/{id}/messages`：检索资料并回答。
- `GET /api/assistant/conversations`：查询历史会话。

## 9. 成本控制

按 40 分钟课堂估算，课后模式的主要成本是语音识别，不是汇报 Agent。以 `gpt-transcribe` 为例，转写约 $0.18；关键帧仅筛选后分析，视觉与汇报通常合计约 $0.01–0.06，单节建议按 $0.19–0.25 的模型预算设计。实时字幕和实时翻译应作为高级能力，按分钟或会员额度控制。

成本控制措施：

- 默认音频课堂模式；视觉只采集并处理关键帧。
- 以画面变化检测去重，限制每节送入视觉模型的图片数量。
- 汇报使用结构化输出和轻量模型；失败时回退抽取式简报。
- 原始视频设短期保留策略；长期保存音频、转录、汇报和关键图片。
- 为每节课记录 ASR、视觉、LLM、存储和网络成本，作为后续计费与限额依据。

## 10. 安全、隐私与合规

- 录制前明确提示课堂录音录像须遵守学校和当地法规，并由用户确认获得必要许可。
- 音频和视频采用私有对象存储、传输加密、用户级访问控制与签名 URL。
- 视频默认不拍摄学生；禁止以产品功能为目的的人脸识别与身份推断。
- 用户可删除原始媒体、单个视觉资产、汇报和对话记录；删除课堂时应级联删除其派生数据。
- 对话 Agent 的检索必须按 `user_id`、课程和课堂范围过滤，并对引用再次校验。

## 11. 分阶段交付

### P0：稳定的音频课堂与自动汇报（2–3 周）

- 保持音频录制独立、可恢复、可分片上传。
- 课堂结束后自动生成结构化课堂汇报；沿用现有抽取式简报作为兜底。
- 汇报每项可跳转到转录与音频时间点。
- 加入处理状态、失败重试、汇报编辑和导出。

### P1：可选板书/PPT采集（2–4 周）

- 音视频权限、状态和上传链路彻底解耦。
- 客户端关键帧筛选、服务端 OCR、图片与课堂时间轴关联。
- 在汇报中展示和管理板书/PPT图片。

### P2：跨课堂学习助手（3–4 周）

- 课程实体、会话历史、按范围的对话页面。
- 跨转录、汇报、OCR 的检索与引用来源卡片。
- 课程资料上传和混合检索。

### P3：主动复习（后续迭代）

- 将疑问、定义和考点生成复习卡、小测与待办。
- 依据用户收藏、问答与答题情况给出复习优先级。

## 12. 验收指标

| 指标 | P0 目标 |
| --- | --- |
| 无摄像头设备的音频课堂成功率 | ≥ 99%（排除用户拒绝麦克风权限） |
| 40 分钟课结束后汇报可用时间 | ≤ 5 分钟 |
| 汇报核心内容带有效引用的比例 | 100% |
| 作业/日期类内容标注待确认的准确性 | 人工抽检 ≥ 95% |
| 用户从汇报跳回音频定位成功率 | ≥ 99% |
| 视觉采集失败导致音频课堂中断 | 0 |

## 13. 首期优先决策

1. 将“音频课堂”作为正式默认模式，视频仅是增强模块。
2. 先交付结构化、可引用、可编辑的课堂汇报，再扩展视觉与跨课程问答。
3. 视觉采用关键帧筛选后处理，不以关键词触发录像，也不逐帧调用大模型。
4. 所有 Agent 输出必须受到 JSON Schema、证据引用和权限边界约束。
